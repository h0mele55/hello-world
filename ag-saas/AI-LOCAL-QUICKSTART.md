# Local Ollama Quickstart (for AI-KIT #31–#32, test purposes)

The exact steps to run a clean-licensed small model **locally** so you can test the AI
features with **no API keys and no cost**. This is the runbook that prompt **#31** (provider
wiring) and **#32** (RAG embeddings) assume. Local only — nothing here is for production
(that's #33+).

Models used:
- **Chat/reasoning:** `qwen3:1.7b` — Apache-2.0, ~1.1 GB download, CPU-friendly. (Bump to
  `qwen3:4b` for better answers, or try `granite4:tiny`/`granite3.3:2b` for tool-heavy JSON.)
- **Embeddings (only needed for #32 RAG):** `nomic-embed-text` — ~270 MB.

Rough resources: ~6–8 GB RAM free is comfortable for the 1.7B + embeddings at Q4 on CPU.
A GPU makes it much faster but is **not required** for testing. Expect a few seconds per
answer on CPU — fine for dev, not for many concurrent users (that's the prod/hosted path).

---

## Option A — Install Ollama natively (simplest)

**macOS / Windows:** download the app from https://ollama.com/download and run it (it starts a
background server on `http://localhost:11434`).

**Linux:**
```bash
curl -fsSL https://ollama.com/install.sh | sh
# starts the ollama systemd service on :11434
```

**Pull the models:**
```bash
ollama pull qwen3:1.7b
ollama pull nomic-embed-text      # only if you're doing #32 (RAG)
ollama list                        # confirm both are present
```

**Verify the OpenAI-compatible endpoint works** (this is the same API the app calls):
```bash
# Chat (OpenAI-compatible)
curl http://localhost:11434/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen3:1.7b",
    "messages": [{"role":"user","content":"In one sentence: when is a good time to spray fungicide?"}]
  }'

# Embeddings (for #32)
curl http://localhost:11434/v1/embeddings \
  -H "Content-Type: application/json" \
  -d '{"model":"nomic-embed-text","input":"powdery mildew on wheat"}'
```
If both return JSON, you're done — the model server is live.

## Option B — Run Ollama in docker-compose (matches the dev stack in #31)

Add to the dev `docker-compose.yml`:
```yaml
  ollama:
    image: ollama/ollama:latest
    ports:
      - "11434:11434"
    volumes:
      - ollama:/root/.ollama
    # GPU (optional, NVIDIA): uncomment to accelerate
    # deploy:
    #   resources:
    #     reservations:
    #       devices:
    #         - capabilities: ["gpu"]

volumes:
  ollama:
```
Then:
```bash
docker compose up -d ollama
# pull models into the container (one-time; persists in the named volume)
docker compose exec ollama ollama pull qwen3:1.7b
docker compose exec ollama ollama pull nomic-embed-text
```
Note: if your **app also runs in compose**, point it at `http://ollama:11434/v1` (service name),
not `localhost`. If the app runs on the host and only Ollama is in compose, use `localhost`.

## App env (matches AI-KIT #31)

`.env.local`:
```bash
AI_BACKEND=openai-compatible
AI_BASE_URL=http://localhost:11434/v1     # or http://ollama:11434/v1 inside compose
AI_API_KEY=ollama                          # any non-empty string; Ollama ignores it
AI_MODEL=qwen3:1.7b
# for #32 RAG:
AI_EMBED_MODEL=nomic-embed-text
```

After #31 lands, the app's `AiProvider` reads these and talks to Ollama with zero code changes
vs. production (prod just swaps `AI_BASE_URL`/`AI_MODEL`/`AI_API_KEY`).

## Smoke test (end to end)

1. `ollama ps` — confirm the model is loaded (or loads on first call).
2. Start the app (`npm run dev`) with the env above.
3. Trigger an AI feature (e.g., the agronomy copilot / a spray-window explanation). You should
   get a response generated by the local model.
4. With #32 applied: ask a question whose answer is in your ingested corpus and confirm the
   answer comes back **with citations** (proves RAG retrieval, not just the base model).

## Troubleshooting

- **`connection refused` on :11434** — Ollama isn't running. Native: open the app / `ollama serve`.
  Compose: `docker compose up -d ollama`.
- **`model 'qwen3:1.7b' not found`** — run the `ollama pull` (or `docker compose exec … pull`).
- **App in compose can't reach `localhost:11434`** — use the service name `http://ollama:11434/v1`.
- **Very slow / high RAM** — you're on CPU; use `qwen3:1.7b` (not larger), close other apps, or
  add a GPU. First call is slower (model load); subsequent calls are faster while it's resident.
- **Structured output looks malformed** — small models occasionally break JSON; #31 includes a
  validate-and-repair fallback and a capability map. Prefer `granite4`/`qwen3:4b` if a feature
  leans hard on strict JSON/tools.
- **Port clash** — set `OLLAMA_HOST=0.0.0.0:11500` (native) or remap the compose port, and update
  `AI_BASE_URL` to match.
